# SISTEMA WEB LOS CHASKIS

## Especificación funcional para implementación en Antigravity IDE

### 1. CONTEXTO GENERAL

Implementar los módulos internos del sistema web:

* **MÓDULO 1:** Administrador General (`ROLE_ADMIN`)
* **MÓDULO 2:** Supervisor de Terminal / Embarque (`ROLE_SUPERVISOR`)

El sistema corresponde a **LOS CHASKIS: Sistema Web Integral de Gestión Operativa y Venta de Pasajes Interprovinciales**.

### REGLAS GENERALES DE IMPLEMENTACIÓN

* Mantener estrictamente el flujo funcional descrito.
* No eliminar funcionalidades.
* No agregar módulos, procesos o estados que no estén especificados.
* Respetar los nombres de tablas, campos y relaciones indicados.
* Implementar la interfaz con diseño institucional y profesional.
* Utilizar **Spring Boot + Spring Security + MySQL** en backend.
* Utilizar **HTML + JavaScript + Bootstrap 5** en frontend.
* Utilizar **Thymeleaf** para las vistas del Backoffice cuando corresponda.
* Utilizar **Chart.js** para los gráficos.
* Aplicar control de acceso mediante roles:

  * `ROLE_ADMIN`
  * `ROLE_SUPERVISOR`
* Las operaciones que modifican información deben persistirse en MySQL.
* Validar formularios tanto en frontend como en backend.
* Mantener una estructura de código organizada y escalable.

---

# MÓDULO 1 — ADMINISTRADOR GENERAL

**Rol:** `ROLE_ADMIN`

El Administrador General representa el Backoffice corporativo del sistema.

Desde este módulo se gestionan:

1. Autenticación y sesión.
2. Dashboard y reportes gerenciales.
3. Flota de buses.
4. Rutas e itinerarios.
5. Programación de viajes.
6. Usuarios y accesos.

---

## 1.1. AUTENTICACIÓN Y CONTROL DE SESIÓN

### Vista

`login.html`

### Objetivo

Permitir que un usuario con rol administrativo ingrese al Backoffice.

### Interfaz

Crear un formulario institucional centrado para LOS CHASKIS.

### Campos

| Campo              | Tipo     |
| ------------------ | -------- |
| Correo Electrónico | Email    |
| Contraseña         | Password |

### Validación

La autenticación debe consultar la tabla:

`usuarios`

Validar:

```text
estado = 1
```

y verificar que el usuario tenga:

```text
id_rol → ROLE_ADMIN
```

La contraseña debe ser validada mediante **Spring Security**.

### Flujo exitoso

Después de autenticarse correctamente:

```text
/login
   ↓
/admin/dashboard
```

### Seguridad

Las rutas `/admin/**` deben estar protegidas para:

```text
ROLE_ADMIN
```

Un usuario sin permisos no debe poder acceder directamente a las vistas administrativas.

### Regla especial al crear un bus

Cuando se registre una nueva unidad:

1. Guardar el bus.
2. Obtener su capacidad.
3. Generar automáticamente los registros correspondientes en `asientos`.
4. Respetar el piso configurado.
5. Asociar los asientos al bus correspondiente.

Ejemplo:

```text
Capacidad = 32

→ generar automáticamente 32 registros en asientos

```

## Campo 2 — Bus Asignado

Desplegable.

```text
estado_bus = 'ACTIVO'
```

---

## Campo 3 — Chofer Principal

Desplegable.

Consultar:

```text
choferes
```

Mostrar únicamente choferes activos.

---

## Campo 4 — Fecha de Salida

```text
DATE
```

---

## Campo 5 — Hora de Salida

```text
TIME
```

---

## Campo 6 — Llegada Estimada

Este dato debe calcularse automáticamente en el backend.

La ruta contiene:

```text
duracion_estimada
```

El backend Spring Boot debe sumar:

```text
fecha_salida
+
hora_salida
+
duracion_estimada
```

para obtener:

```text
fecha_llegada_estimada
hora_llegada_estimada
```

No solicitar manualmente estos valores al usuario.

---

## Campo 7 — Precio Base

```text
DECIMAL(10,2)
```

Mostrar en soles:

```text
S/
```

# MÓDULO 2 — SUPERVISOR DE TERMINAL / EMBARQUE

**Rol:** `ROLE_SUPERVISOR`

Este módulo está orientado a la operación en plataforma dentro de la terminal.

### Objetivo principal

Controlar el embarque de pasajeros y registrar el abordaje en tiempo real.

Corresponde al:

```text
CU-03: Control de Abordaje
```

El supervisor debe poder:

1. Buscar el viaje/bus.
2. Visualizar la información de la unidad.
3. Revisar la ocupación.
4. Visualizar el manifiesto.
5. Registrar pasajeros que abordaron.
6. Registrar pasajeros ausentes.
7. Visualizar y gestionar los asientos.
8. Iniciar el viaje.
9. Finalizar el viaje.

# ACCIONES DE EMBARQUE

## Acción "Abordó"

Botón verde:

```text
✓ Abordó
```

Al hacer clic:

1. Cambiar:

```text
estado_abordaje = 'ABORDO'
```

2. Actualizar:

```text
fecha_abordaje
```

con la fecha/hora actual.

3. Registrar:

```text
id_usuario_supervisor
```

correspondiente al supervisor autenticado.

4. Persistir los cambios en:

```text
detalle_venta
```

5. Actualizar inmediatamente la interfaz.

---

## Acción "Ausente"

Botón rojo:

```text
Ausente
```

Al hacer clic:

```text
estado_abordaje = 'AUSENTE'
```

Persistir el cambio en la base de datos y actualizar inmediatamente los indicadores y el manifiesto.
